------------------------------------------------------------------------------
P1 — Core engine + CounterWorld
------------------------------------------------------------------------------

P1-1  LOW     Pause semantics: an in-flight step may complete after Pause()
              returns (documented "takes effect at the next step boundary").
              If a strict "no step after Pause() returns" guarantee is wanted,
              add a drain handshake in the runtime loop.

P1-2  FIXED   run() has no deferred cancel()/close(done). A panicking model
              877e5f0 leaves the simulation in StateRunning, leaks the watcher
              goroutine, and hangs Wait(). Add defer cancel + close(done), and
              consider panic recovery for fault isolation (spec sec. 35/36).
              -> Fixed: deferred finalization + panic recovery turns a model
              panic into StateFailed and guarantees Wait() returns
              (TestModelPanicRecovery, TestModelPanicWaitDoesNotHang).

P1-3  LOW     Step() is allowed while the simulation is paused (it only rejects
              StateRunning). Decide whether paused + Step should be rejected.

P1-4  FIXED   begin() resets the steps counter on every Run/RunN/Start, so
              877e5f0 Ticks() is per-run, not cumulative. Document this explicitly.
              -> Fixed: Ticks() doc now states it counts the current run.

P1-5  INFO    EntityManager.Each / Column.Each release locks and iterate
              aliased slices. Safe while single-threaded; parallel code must
              not mutate membership during iteration (P3 already enforces this
              via the System.Run shard contract).

P1-6  INFO    tickExecutor advances the clock AFTER Step, so the first Step
              observes Tick()==0. Confirm/document the tick-index semantics.

------------------------------------------------------------------------------
P2 — Discrete-event engine
------------------------------------------------------------------------------

P2-1  FIXED   RunUntil's predicate is now evaluated once BEFORE the first step
              877e5f0 (doc comment says "once after each step"). If pred is true at
              entry the run stops with zero steps. Align doc and behavior.
              -> Fixed: run() doc now says the limit is consulted before each
              step, matching behavior.

P2-2  LOW     MaxTime is exclusive: an event scheduled exactly at MaxTime is
              skipped (peek >= MaxTime). The test codifies this; confirm it is
              the intended "run until time" semantics.

P2-3  FIXED   TestEventModeEmptyQueue contains dead code (emptyModel type and
              877e5f0 an unused m variable). Remove.
              -> Fixed: dead code removed.

P2-4  FIXED   Clock.AdvanceTime has no monotonicity guard: a buggy model can
              877e5f0 schedule into the past and loop forever. Add a guard and/or a
              max-events/runaway protection (relevant to P7 timeouts).
              -> Fixed: the event executor rejects events scheduled into the
              past with an error (TestEventInPastRejected). Runaway same-time
              event loops are still possible; consider a max-events guard in P7.

P2-5  INFO    Event-mode Ticks() now counts processed events (not the final
              empty pop). Consistent with the empty-queue test; document.

------------------------------------------------------------------------------
P3 — Parallel execution
------------------------------------------------------------------------------

P3-1  FIXED   Benchmark warm-up: the first Step builds each system's entity set
              877e5f0 (~150 MB one-time at 1M entities) and lands inside measured ops
              because ResetTimer precedes the loop. Run one Step before
              ResetTimer so steady-state per-tick cost is measured.
              -> Fixed: warm-up Step added before ResetTimer.

P3-2  LOW     At small N parallel overhead exceeds benefit (10k: parallel was
              slower than serial). Consider falling back to the inline path
              below an entity-count threshold.

P3-3  INFO    runLevelParallel nests system-level and shard-level goroutines
              (up to k*workers). Bounded, but note the total when many systems
              share a level.

P3-4  INFO    If one shard errors, the other shards still run to completion,
              so failed ticks can leave partially updated state. Document the
              error-path semantics (determinism is only guaranteed on the
              success path).

P4 — Snapshots / restore / validate
------------------------------------------------------------------------------

P4-1  FIXED   Event payloads lose their Go type on restore: payloads come back
              877e5f0 as json.RawMessage, so models doing e.Payload.(int) (e.g. the
              cascade model) fail after restore+continue. Reproduced
              experimentally. Add a payload type-codec registry. Until fixed,
              full event-mode replay (spec sec. 16 / DoD "deterministic replay")
              is not satisfied for typed payloads.
              -> Fixed: World.RegisterPayloadType + type envelope preserve
              registered payload types on restore; unregistered payloads
              restore as json.RawMessage (documented). Re-verified with the
              original reproduction: now passes.

P4-2  FIXED   Snapshot() has no running-state check and captures each structure
              877e5f0 under separate locks, so snapshotting mid-run can produce a torn
              snapshot (entities from one tick, components from another).
              Restore() rejects a running sim; Snapshot() should too (or pause
              during capture).
              -> Fixed: Simulation.Snapshot rejects StateRunning. RESIDUAL
              EDGE (open): Pause() returns before an already-started step
              finishes, so Snapshot() taken immediately after Pause() can still
              observe the in-flight step. A quiescence handshake (P1-1) would
              close this fully.

P4-3  FIXED   Tags and resources are not serialized: TagStore, TagRegistry, and
              877e5f0 ResourceRegistry are absent from the snapshot, so models using
              them silently lose state on restore. Add them to the snapshot
              (spec sec. 15 "world state").
              -> Fixed: tag names + per-entity bitsets and typed resources are
              now serialized/restored (TestTagsResourcesSnapshot).

P4-4  FIXED   Restore does not bump the World structural revision, so a reused
              877e5f0 scheduler's entity-set cache can serve stale shards after a
              restore that changes entity membership. Unreachable via
              SystemModel today, but harden now (bump revision on restore).
              -> Fixed: World.Restore bumps the structural revision.

P4-5  FIXED   Model-specific configuration (e.g. CounterWorld.N,
              877e5f0 IncrementMax) is not part of the snapshot; the caller must
              configure the model identically on restore. Spec sec. 15 lists
              "model configuration" as snapshot content — consider a
              model-provided config codec.
              -> Fixed: SnapshotModel interface (SnapshotConfig/RestoreConfig);
              CounterWorld implements it (TestSnapshotCapturesModelConfig).

P4-6  LOW     Runtime-level steps counter and lifecycle state are not restored,
              so Ticks() after restore+continue counts only post-restore
              ticks. Document or restore.

P4-7  INFO    Doc claim "two worlds in an identical state produce identical
              snapshots" only holds when internal heap layout also matches.
              Restore round-trip is verified byte-identical; just soften the
              wording.

P4-8  FIXED   modeFromString silently defaults unknown mode strings to tick.
              877e5f0 Snapshot validation could reject unknown mode instead.
              -> Fixed: unknown mode now returns an error during restore.

P4-9  INFO    Engine version check is exact-match. Fine for now; define a
              compatibility policy before any 1.0 release.

P5 — Persistence (pgx + sqlc, migrations, model registry)
------------------------------------------------------------------------------

P5-1  FIXED    Simulation seeds are stored as BIGINT (signed int64), but the
               00cc8e4 engine's Config.Seed is uint64. Seeds above 2^63-1 cannot be
               persisted/restored. Either constrain seed values or switch the
               column to NUMERIC(20,0)/two-int64 encoding.
               -> Fixed by constraint: the runner rejects seeds above
               math.MaxInt64 with a clear error (documented tradeoff).

P5-2  LOW      The migration runner records only (version, name, applied_at)
               in schema_migrations — no SQL checksum. A migration file edited
               after being applied is not detected. Add a checksum column for
               integrity.

P5-3  LOW      Rollback silently no-ops (and unrecords) a migration whose down
               file is empty. Prefer an explicit error on a missing/empty down
               file.

P5-4  INFO     Registry "latest" uses compareVersion, which treats
               "1.2.3-alpha" equal to "1.2.3" (pre-release suffix ignored) and
               does not order pre-releases relative to releases. Acceptable
               for now; document the policy.

P5-5  INFO     Local dev credentials live in a gitignored .env with a plaintext
               password. Fine for local development; production secrets must
               come from environment/secret management (see P8 security work).

P6 — REST API + CLI
------------------------------------------------------------------------------

P6-1  FIXED    Stop/stop race: when Stop() cancels the run context while a step
               00cc8e4 is in flight, the scheduler returns context.Canceled, which the
               runtime misclassifies as a model error — the simulation ends
               state=failed (err="context canceled") instead of stopped.
               Reproduced at engine level: 3 of 5 runs failed after Stop.
               -> Fixed: run() now treats a step error that coincides with run
               context cancellation as a stop, not a failure. Stress re-check:
               20/20 clean stops (was 3/5 failing), plus a deterministic
               regression test (TestStopMidStepIsStoppedNotFailed).

P6-2  FIXED    Manager in-memory record status is stale: lifecycle operations
               00cc8e4 persist the status to PostgreSQL but never update mg.info.Status,
               so GET /api/v1/simulations/{id} and the list endpoint return
               "created" even while the live /state endpoint reports "running".
               Confirmed in E2E.
               -> Fixed: Get/List now return the live simulation state.
               Re-verified: record shows "running" while running.

P6-3  FIXED    Replay runs synchronously on context.Background() and never
               00cc8e4 returns for an unbounded simulation (max_ticks=0), blocking the
               HTTP handler forever and preventing graceful shutdown (observed:
               shutdown timed out after 10s).
               -> Fixed: replay is now asynchronous (Start + watcher) and
               returns immediately. Re-verified: unbounded replay returned in
               39ms; simulation continued in the background.

P6-4  FIXED    DELETE removes only the in-memory entry; the PostgreSQL row
               00cc8e4 remains. Add a real delete query.
               -> Fixed: DeleteSimulation query added; re-verified the row is
               gone from PostgreSQL after DELETE (204).

P6-5  PARTIAL  CLI is missing restore/workers/benchmark/model-inspect commands
               from spec sec. 39.
               -> Fixed: `model <id>` and `restore <id> <file>` added. Still
               missing: `workers` (belongs to P7) and `benchmark` (belongs to
               performance work); track those in their own phases.

P6-6  FIXED    Simulation errors like ErrAlreadyRunning (e.g. snapshot while
               00cc8e4 running) surface as HTTP 500; map them to 409 Conflict.
               -> Fixed: ErrAlreadyRunning/ErrNotRunning map to 409.
               Re-verified: second start returns 409.

P6-8  FIXED    Seeds above 2^63-1 cannot fit PostgreSQL BIGINT.
               00cc8e4 -> Fixed: Create rejects seed > math.MaxInt64 with a clear

P6-7  INFO     Replay determinism verified end-to-end for a bounded run (1000

Code terseness (user requirement: prefer short, clear code)
------------------------------------------------------------------------------

The runner wants needless verbosity trimmed: a 30-line block that can be 10
lines should be 10. Concrete reductions identified so far (hand-written code,
excluding sqlc-generated queries.sql.go):

TRIM-1  internal/runner/manager.go — Start/Pause/Resume/Stop/Step are five
        near-identical ~9-line wrappers (~42 lines). One helper:
          func (m *Manager) control(id string, f func(*simulation.Simulation) error, status string) error
        collapses them to one-liners (~12 lines total). Save ~30 lines.

TRIM-2  internal/api/handlers.go — start/pause/resume/stop/step endpoints are
        seven ~6-line near-identical handlers (~42 lines). A single
        lifecycleAction(id, action func() error, status string) helper with
        per-endpoint one-liners saves ~25 lines.

TRIM-3  pkg/simulation/scheduler.go — runLevelParallel and runSystem each
        re-implement the same wg + errCh + bounded-pool pattern (~40 lines).
        One runConcurrent(n, fn) helper saves ~15 lines.

TRIM-4  cmd/cli/main.go — doStatus/doMetrics (8 lines each) only differ by
        path suffix; a doGet(id, subpath) helper saves ~8 lines. doModels/
        doModel are already minimal.

TRIM-5  internal/persistence/store.go — ListModels/ListSimulations/ListSnapshots
        share the same rows→slice shape; a small generic mapper could save
        ~10 lines, though current form is acceptable (low priority).

Estimated total: ~90 lines removed with zero behavior change and no loss of
readability. Apply the same standard to all new P7+ code: prefer one-line
delegates and shared helpers over repeated 8-10-line wrappers.

TRIM-6  erl_crash.dump (~1 MB, RabbitMQ/Erlang crash dump) appeared in the repo
        root during P7 setup. It must never be committed; .gitignore was updated
        to exclude it. Confirm the working tree is clean of it at commit time.

P7 — Distributed workers (broker + Redis + jobs)
------------------------------------------------------------------------------

P7-1  FIXED    Idempotency breaks retry/DLQ. queue.Consume claims
               da22b75 "job:processed:<id>" BEFORE running the handler and never
               releases it on failure, so with Redis enabled the first failed
               attempt is claimed, and every retry delivery of the same job ID
               is silently dropped.
               -> Fixed: the claim is released on failure so retries can
               re-claim; success keeps the 24h processed marker.
               TestRetryWithRedis added. Re-verified end-to-end: with Redis on,
               a failing job now retries and lands in the DLQ after 2 attempts
               (previously 0 outcomes).

P7-2  FIXED    The RabbitMQ broker has no reconnect/recovery: a dropped
               da22b75 connection or closed consume channel terminates Consume and the
               worker exits.
               -> Fixed: reconnect with bounded exponential backoff (1s..30s)
               on consume-channel loss and reconnect-once on publish failure.

P7-3  FIXED    cmd/worker exits with code 1 and logs "ERROR worker: context
               da22b75 canceled" on SIGINT/SIGTERM.
               -> Fixed: clean shutdown now exits 0 and logs "worker stopped"
               (verified).

P7-4  FIXED    internal/coord has no unit tests (Heartbeat/Alive/Claim).
               da22b75 -> Fixed: internal/coord/redis_test.go added (65 lines).

P7-5  INFO     Port 6379 is served by a Valkey instance from another project,
